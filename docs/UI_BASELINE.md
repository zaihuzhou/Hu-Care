# 祜·Care UI 基准

- 状态：V0.1 / 约束说明
- 重要：以用户指定的“最喜欢的上一版界面”为视觉基准，不擅自重新设计或用最新生成图替代
- 用户已在对话中提供 Hu-Fin AI 投资副驾驶工作台截图，作为本项目的视觉与交互参考。截图尚未作为图片文件提交到仓库；若要让开发者在仓库中直接查看，后续需将原图加入设计资料目录。

## 1. 已确认的参考图特征

- 左侧深色固定导航栏，包含工作台入口、研究功能、项目库、知识/方法和设置，以及最近工作列表。
- 顶部提供全局搜索、通知、任务入口和用户菜单。
- 中央主区域以欢迎/任务输入区为核心，下面展示投资关注项目、AI 发现的机会和市场概览。
- 右侧为 AI 研究伙伴面板，展示研究进度、已完成步骤、下一步建议和快捷输入。
- 页面下方有产品理念、核心交互步骤和 AI 工作方式说明。
- 整体使用浅色背景、深蓝侧栏、蓝色强调色、圆角卡片和细边框；信息密度较高但区块清晰。

这些是截图可见的基准描述。后续实现应尽量保留主要布局和视觉层级，不擅自重新构思一套界面。

## 2. 设计目标

界面应服务于投资研究工作：信息密度高但有层次，突出项目、任务、证据、风险和判断；避免做成泛化聊天机器人或炫技型 AI 仪表盘。

## 3. 基准规则

1. **沿用用户选定的版本**：除非用户明确要求，不更换整体布局、视觉语言和主要交互。
2. **只做必要的 MVP 收敛**：在既有设计上纳入首版必须能力，不借机扩展大量新模块。
3. **证据可见**：研究结论附近应能查看来源、证据类型、日期和验证状态。
4. **状态清楚**：任务运行中、等待人工确认、成功、失败和待验证均有明确呈现。
5. **人工掌控**：确认、修改、驳回和重试等动作应清晰，不把 AI 输出呈现为自动定论。
6. **一致性优先**：统一导航、间距、字体层级、表格、状态标识和空/错状态。

## 4. 首版信息架构（待与参考图对齐）

- 工作台 / AI Copilot
- 项目库
- 项目详情：概览、材料与来源、研究任务、发现与风险、报告
- 投资判断与复盘
- 技能/连接器状态（可先放在设置或诊断区）

导航名称和布局以用户最终确认的参考图为准。

## 5. MVP 首版界面必须支持的五项能力

1. 项目可发现：能创建、搜索和打开项目。
2. 任务可追踪：能看到任务状态、执行结果和失败原因。
3. 证据可核验：结论能跳转至来源或明确显示缺少来源。
4. 风险与待验证事项可管理：能查看、更新状态并关联证据。
5. 判断可复盘：记录判断、关键假设和后续结果。

## 6. 不应出现

- 为了视觉效果而隐藏证据或任务失败信息。
- 无依据的精确评分、自动投资建议标签或虚构数据。
- 在界面中暴露密钥、原始认证令牌或不必要的敏感内容。
- 没有真实功能支撑的按钮和装饰性控制。
- 未经用户确认就改动其选定的主要布局。

## 7. 视觉验收清单

- [ ] 与用户指定的参考版本在主要布局和视觉语言上保持一致。
- [ ] 首页能明确区分 Copilot 入口、项目与近期任务。
- [ ] 项目详情能快速找到材料、证据、风险和研究结论。
- [ ] 任务状态与人工确认状态可一眼识别。
- [ ] 空状态、加载状态、错误状态和无证据状态都有设计。
- [ ] 桌面端优先适配，同时避免窄屏内容溢出。
