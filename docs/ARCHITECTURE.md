# 祜·Care 技术架构基线

- 状态：V0.1 / 提议方案，尚待确认
- 原则：模块化单体优先，接口清晰，避免过早拆分微服务
- 当前阶段：只确定边界与验证项，不实现业务代码

## 1. 逻辑架构

```text
Web 工作台
  └── AI Copilot 入口
       ├── 投资研究引擎
       ├── 投资认知引擎
       └── 任务/工作流编排
              ├── Skills 适配层
              ├── 数据连接器
              └── 模型适配层

共享领域能力
  ├── 项目与材料
  ├── 来源与证据
  ├── 任务与执行记录
  ├── 判断与复盘
  ├── 个人记忆与检索
  └── 权限、审计与配置

基础设施
  ├── 关系数据库
  ├── 文件/对象存储
  ├── 全文与向量检索（按需启用）
  └── 日志、测试与部署
```

## 2. 推荐技术栈（提议，非最终决定）

- Web：Next.js、React、TypeScript
- UI：Tailwind CSS、shadcn/ui；组件设计应服从已选定的 UI 基准
- API：Python + FastAPI（若现有 Skills 更适合 Python，优先复用）
- 数据库：PostgreSQL
- 检索：先采用 PostgreSQL 全文检索；确认语义检索需求后再启用 pgvector
- 本地开发：Docker Compose（在确认运行环境后采用）
- 测试：前端组件/流程测试、API 单元测试、关键集成测试

在技能审计和环境检查完成前，不将以上提议当作已定技术决策。

## 3. 主要模块边界

### Web 应用
负责导航、项目视图、任务状态、证据浏览、报告查看、人工确认与复盘界面。不得把供应商密钥放在浏览器端。

### API / 应用服务
负责身份与会话边界、业务校验、项目/证据/任务接口、技能调用授权、工作流状态以及审计记录。

### 领域模块
- Project：项目与项目元数据。
- Source / Evidence：来源、材料、事实摘录、证据与结论关联。
- Task / Workflow：任务生命周期、步骤、重试与人工确认。
- Skill Adapter：统一技能注册、输入输出、超时、错误与版本信息。
- Investment Memory：判断、假设、复盘及经过用户允许保存的个人知识。
- Connector：外部数据源接入、限流、授权、数据新鲜度与来源元数据。

### 模型适配层
对不同模型提供方进行隔离，统一超时、错误、用量记录和结构化输出校验。模型输出应视为待验证内容，不直接视为事实。

## 4. 关键请求流程

1. 用户从 Copilot 或项目页创建研究任务。
2. API 校验用户权限、项目范围和任务参数。
3. 编排器创建任务记录，并选择所需技能/连接器。
4. 技能适配层执行任务；输入、版本、状态和错误均可追踪。
5. 输出经过格式校验，重要事实和结论关联来源。
6. 用户查看结果并确认、修改或要求补充验证。
7. 确认后的判断按用户选择写入项目记录/个人认知记录。

## 5. 非功能要求

- 凭证只存于服务端受控配置或密钥管理系统，不进入 Git、前端包或日志。
- 对外部调用设置超时、限流、重试上限和可解释错误。
- 任务执行可观察、可取消（如执行环境支持）、可重试且避免重复写入。
- 数据模型保留创建时间、更新时间、来源和必要的版本信息。
- 上传文件需限制类型/大小，并考虑恶意文件与敏感信息风险。
- 所有关键投资结论应可追溯；日志不得无差别记录原始敏感材料。
- 先采用单一部署单元，只有在吞吐、隔离或维护需求明确时才拆服务。

## 6. 安全边界

- 外部网页、文档、检索结果和模型输出均视为不可信数据，不允许其覆盖系统规则或触发未经授权的动作。
- 外部连接器使用最小权限；密钥可轮换，并提供撤销路径。
- 关键操作（导出、删除、外部发送、记忆写入）应有明确用户意图和确认机制。
- MVP 默认单用户场景，但数据访问层应避免跨用户数据混淆，为未来权限体系留出边界。

## 7. 需要在 S0 验证

- GitHub 仓库当前为空；确认目录与开发环境。
- 检查 Skills 的文件、依赖、运行命令、授权和输入输出协议。
- 选定模型提供方及调用方式。
- 确认部署目标与数据库托管方式。
- 验证候选数据源的实际接入条件。
