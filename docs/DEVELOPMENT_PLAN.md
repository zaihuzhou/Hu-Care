# 祜·Care 开发计划与验收基线

- 状态：V0.1 / 初始计划
- 当前阶段：S0 产品与工程准备
- 约束：在完成准备和用户确认前，不开始业务代码实现

## S0 — 基线与现状审计

### 工作项
- 确认 PRD、架构、数据模型和 UI 基准。
- 盘点现有 Skills：文件、依赖、运行入口、输入输出、权限和可复用程度。
- 验证开发环境、模型调用方式和外部数据源接入条件。
- 确认技术栈和项目目录结构。
- 识别安全、数据保留与凭证管理要求。

### 验收
- 技术选型从“提议”变为明确决策，或记录未决原因。
- 每个候选 Skill 有审计结论：可直接复用、需适配、不可用/待验证。
- 外部数据源有接入状态与授权说明，不把候选项误报为已接通。
- UI 参考版本得到明确指认。

## S1 — 工作台与项目基础

### 工作项
- 建立基础应用骨架、配置和开发/测试启动方式。
- 实现项目列表、项目创建、项目详情。
- 实现来源/材料登记与基本文件元数据。
- 建立数据库迁移、错误处理和基础测试。

### 验收
- 项目数据可持久化并可重新读取。
- 基础导航与 UI 基准一致。
- 关键 API 有校验和测试。

## S2 — 投资研究引擎

### 工作项
- 建立 Skill 注册表和统一适配协议。
- 接入通过 S0 审计的尽调、财务分析和 PE 技能。
- 建立任务/执行记录、状态轮询或更新机制。
- 建立证据、发现、风险与报告草稿视图。

### 验收
- 用户可以启动研究任务并追踪状态。
- 成功、失败、超时和重试路径可解释。
- 结论与来源/证据关联；没有证据的结论明确标注待验证。
- 模型或技能输出经过结构化校验后再写入领域记录。

## S3 — 投资认知与复盘

### 工作项
- 记录投资判断、投资假设和后续验证结果。
- 建立项目复盘流程。
- 建立用户可查看、编辑和删除的记忆条目。
- 设计检索范围和记忆写入确认策略。

### 验收
- 判断能关联论据、假设与项目结果。
- 复盘可以回看原始判断及其时间点。
- 记忆写入透明、可控制，不自动永久保存所有对话。

## S4 — 工作流与连接器扩展

### 工作项
- 将常见研究流程整理为可配置工作流模板。
- 加入人工确认点、有限重试和失败恢复。
- 在授权和可用性核实后接入外部数据源。
- 为未来协作、权限和审计扩展预留接口。

### 验收
- 工作流步骤、状态、输入输出和人工确认均可追踪。
- 连接器失败不会伪造数据或静默覆盖已有证据。
- 外部数据来源和获取时间可追溯。

## 交付节奏与质量门槛

- 每个阶段先定义可验证的验收标准，再开始实现。
- 优先端到端打通最小真实流程，避免先堆大量抽象层。
- 每次提交说明变更范围、测试方式和未解决问题。
- 不将密钥、个人敏感数据或未授权第三方材料提交到仓库。
- 在用户确认前，不自动更改已选定的 UI 参考基准。
